# ForAPI 首页重构方案

> 目标：把首页从「一个 API 网关的落地页」重构为「一个 AI 创作平台的首页」。
> 做法是**重写**，不是在现有版面上修补。

---

## 一、问题诊断

### 1.1 当前首页在讲什么

现有 `frontend/src/views/HomeView.vue`（2061 行，7 个 section）的叙事顺序是：

```
Hero：/v1/chat → 网关 → 三条上游通道（SVG 路由图 + 熔断标注）
  ↓
指标条：可用模型 / 上游平台 / 已处理请求 / 用量结算
  ↓
工作台板块（插入在第二屏，已被降级为配角）
  ↓
上游 provider 份额条
  ↓
模型与费率表
  ↓
「这一层替你做四件事」：负载选通道 / 故障收敛 / 请求可追溯 / token 结算
  ↓
接入三步：注册 → 创建 Key → 改 base URL
  ↓
request.sh 代码块
```

**问题不在于这些内容不真实**——它们都是真的，而且做得挺细（路由图是纯 SVG，熔断标注、流动数据包都考虑到了）。
问题在于**这是产品的一个侧面，却被当成了产品本身**。

### 1.2 三个结构性问题

**（一）主语错了**

Hero 大标题是「一个接口，接上你需要的每个模型」，副标题讲 base URL 和 SDK。
但 ForAPI 真正的主语是**作品**，不是**接口**。用户来这里是想要一张图、一段视频，不是一段 curl。

上线数据也印证了这点：`site_subtitle = "All AI, One API"`、线上 `<title>` 是
`ForApi - AI API Gateway`。这两处把「AI API Gateway」写成了品牌定义，而产品实际已经是一个
创作平台——`/studio/` 的无限画布、视频工作台、提示词库、素材库、模型广场都是创作向的。

**（二）工作台被放错了位置**

工作台（画布 / 图片创作 / 视频创作 / 提示词库 / 我的资产）是 ForAPI 区别于任何一家 API 转售站的
核心资产，但它在首页的**第二屏**，而且用「同一个账号里还有一套创作工具」这种措辞——
**「还有」两个字把它说成了附赠品**。

侧栏里它是一个独立分组（`nav.workbench`），五项功能是并列的一等公民；
首页却把它降级成 API 产品的衍生品。这是首页和产品实际结构不一致。

**（三）七段平铺，没有主线**

现在 7 个 section 依次是 Hero / 工作台 / 上游 / 模型费率 / 四能力 / 接入 / 代码。
其中「上游」「四能力」「接入」「代码」四段全在讲同一件事：**怎么把 API 接进来**。
占了将近一半的篇幅，讲了四遍。

### 1.3 但有一件事不能丢

API 能力本身是真实需求——`/docs`、`/model-plaza`、密钥管理、用量记录都还在，
开发者和企业客户仍然靠这条路径付费。**重构不等于砍掉 API 叙事，而是把它挪到正确的位置。**

正确的位置是：**从次要入口变成「也是一个入口」**，而不是占据首屏。

## 二、重构原则

| # | 原则 | 含义 |
|---|---|---|
| 1 | **主语是作品，不是接口** | 首屏要让人看到「这里能做出什么」，而不是「这里能调什么」 |
| 2 | **工作台升为主线** | 创作入口进首屏，与 API 并列为两大场景，不再是「附加功能」 |
| 3 | **每个平台只讲一次** | 四段 API 叙事合并成一段 |
| 4 | **段数减半** | 7 段 → 4 段。信息密度靠排版解决，不靠加段落 |
| 5 | **版面原则不变** | 沿用现有 `.lp-*` 的单一轴线、发丝线、无卡片原则（这套做得很好，不动） |
| 6 | **令牌不变** | 沿用 `tokens-forapi.css`。首页不引入任何新色值 |

**第 5、6 条是硬约束。** 现有首页的视觉规范（不用圆角阴影卡片、用发丝线分区、唯一高饱和面积留给收尾区块）
已经是这个品牌该有的样子，重构只改内容结构与叙事，不推翻视觉语言。

## 三、目标信息架构

### 3.1 新结构（4 段）

```
① Hero —— 「一句话，生成一整支片子」
   主 CTA：开始创作 →  /workbench/canvas
   次 CTA：看看能做什么 → 锚点跳到段②
   背景：极简的创作链路示意（提示词 → 图 → 视频），不再是 /v1/chat 路由图

② 两大场景 —— 并列双栏
   左：创作工作台（5 项功能 + 一句话说明）
   右：API 接入（改一行 base URL，SDK 不用换）
   两个入口平级，各自给出「适合谁」

③ 模型与能力 —— 数据说话
   模型广场的模型（按能力分组，不是按上游平台）
   作品示例位（画廊占位）

④ 收尾 —— 一个动作 + 一行信任信息
   「注册就能开始，不用绑卡」
```

### 3.2 删除与合并

| 现有 | 处置 | 理由 |
|---|---|---|
| Hero 路由图（SVG 熔断图） | **替换**为创作链路示意 | 主语错误 |
| 指标条 | **保留但改口径** | 「已处理请求」→「已生成作品」，否则仍是 API 味 |
| 工作台板块 | **提为段②左栏** | 升为主线 |
| 上游 provider 份额 | **删除** | 纯网关内部结构，普通用户不关心 |
| 模型与费率表 | **保留并改造** | 费率信息对 API 用户有价值，但改为按能力分组 |
| 四能力卡片 | **合并进段②右栏** | 与「接入」重复 |
| 接入三步 + request.sh | **合并成一段** | 两处讲同一件事 |
| 尾页 CTA | **保留** | 收尾区块的高饱和面积原则不变 |

### 3.3 API 叙事怎么保留而不喧宾夺主

不删，但**降级 + 后置 + 收窄**：

- Hero 只保留一句 `base URL` 作为次要信息（放在「API 接入」那一栏里）
- 代码块、协议兼容、SDK 说明全部归入段②右栏
- 面向开发者的完整内容交给 `/docs`，首页只做「看一眼」的深度

## 四、三版设计方向

三版的**骨架是同一套**（4 段结构），差别在**首屏怎么表达「这里能做什么」**。

### A 版 · 作品优先（推荐）

首屏直接给出作品的样子：左列主张与 CTA，右列是一张**作品墙**——真实的图/视频卡片，
带生成参数标注（模型、尺寸、时长）。

- 主张：「一句话，生成一整支片子」
- 视觉重心：作品
- 适合：面向内容创作者、小团队、品牌方，转化路径最短
- 风险：作品图需要真实素材，前期可用参数化占位

### B 版 · 画布优先

首屏右侧直接画一张**无限画布的界面示意**（节点、连线、参考图），
把「作品墙」换成「你将操作的界面」。

- 主张：「把提示词、图片和视频，连成一条流水线」
- 视觉重心：界面
- 适合：熟悉节点式工具的用户（设计、剪辑、AI 绘画人群）
- 风险：对没接触过画布的人门槛偏高，需要文案兜底

### C 版 · 双入口分屏

首屏左右分屏，左「我来做作品」，右「我来接 API」，各配一套视觉。
把「创作 vs 接入」的对立提前到第一屏。

- 主张：首屏即分流
- 视觉重心：并列
- 适合：两类用户比例接近、且不想让任一方觉得被冷落
- 风险：首屏信息量翻倍，且**放弃了「ForAPI 是什么」的统一叙事**

### 推荐

**A 版为主，C 版作为可切换的次选。**

理由：A 版最直接解决用户提出的「太偏 API」问题——首屏完全由作品主导，API 退到第二屏右栏。
而 C 版的双入口本质是把 A 版的段②提到首屏，可以作为 A 版的一个变体（A/B 测或分人群）。

B 版不建议作为主推：无限画布是**进阶功能**，把它放在首屏会让只会「一句话出图」的用户望而却步。

## 五、实施计划

### 阶段 1 · 设计稿（本次交付）

- `design/DESIGN-HOME-REWORK.md` —— 本文档
- `design/preview/home-rework-a.html` —— A 版设计稿
- `design/preview/home-rework-b.html` —— B 版设计稿
- `design/preview/home-rework-c.html` —— C 版设计稿

设计稿沿用 `design/preview/index.html` 的做法：自包含 HTML + 内联 token，
可单独打开评审，不依赖构建。

### 阶段 2 · 重写落地页

- `frontend/src/views/HomeView.vue` —— **重写**，不是改
- `frontend/src/i18n/locales/{zh,en}/landing.ts` —— `home.lp.*` 文案重写
- 复用现有 `.lp-*` 样式骨架，替换内容与图形

### 阶段 3 · 配置与文案同步

以下两项是**后台配置**，不是代码，但它们比代码更能决定「首页像不像 API 产品」：

| 配置项 | 当前值 | 建议值 |
|---|---|---|
| `site_subtitle` | `All AI, One API` | `AI 创作与模型调用，一个账号` |
| 站点 `<title>` | `ForApi - AI API Gateway` | `ForApi - AI 创作与模型调用` |

> 站内另有一处需要同步：`/admin/oauth-provider` 的 `app_name` 当前是 `ForAiVideo`，
> 而视频工作台登录页的品牌文案是「ForAPI 视频工作台」。三处命名不统一，
> 重构首页时应一并收敛到 `ForApi`。

### 阶段 4 · 验证

- 首页 CTA 的目标路由是否正确（未登录 → 登录 → 回跳）
- `showWorkbench` 的三条前置条件（backendMode / simpleMode / 登录态）仍生效
- 深浅色两套
- 窄视口

## 六、需要你拍板的

1. **选哪一版**（A / B / C，或 A 为主 + C 作变体）
2. **站点副标题与 title** 改成什么——上面的建议值可以直接用，也可以你给一句
3. **`/docs` 与首页的分工**：首页保留多深？我倾向首页只留「改一行 base URL」+ 一句 SDK 兼容，
   协议细节全交给 `/docs`
4. **作品素材**：A 版需要真实作品图。现在还没有，是先做参数化占位，还是你提供一批真实素材？
5. **指标条口径**：「已处理请求」改成「已生成作品」——数字从哪来？
   （需要后端加一个统计口径，或者只保留静态宣传数字）
