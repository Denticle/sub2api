## Why

一把 API Key 现在只能绑一个分组（`api_keys.group_id`）。用户要同时用 Claude、GPT、图片、视频等模型，就得建多把密钥；工作台自动创建的「工作台」密钥只能绑管理员指定的一个分组，那个分组没有的模型在工作台里看不到也调不通。同类站点已经提供「一把密钥挂多个分组、按顺序尝试、跳过不支持该模型的分组」的智能路由，用户拿来对比时会认为我们的工作台「分组有问题」。

## What Changes

- API Key 可以绑定**多个有序分组**。第一个分组即「主路由」，与现有 `group_id` 保持一致，旧数据和只绑一个分组的密钥行为不变。
- 网关在**选号之前**为每个请求选组：按顺序跳过以下分组，用第一个合格的分组处理整条请求（计费倍率、订阅额度、模型白名单、账号调度都按这个分组）：
  - 分组停用、已删除，或用户已无权使用；
  - 分组白名单不允许该模型；
  - 分组里没有任何账号配置了该模型；
  - 订阅分组没有有效订阅，或日/周/月额度已用完；
  - 分组当前没有可调度账号（全部限流、过载、暂停）。
- 不带模型的请求（`/v1/models`、视频状态查询、用量查询等）有明确规则：模型列表取各分组的并集；视频状态与内容查询回到创建任务时用的分组；其余走主路由。
- 新增密钥分组模式：
  - **手动**：用户在「API 密钥」创建、编辑弹窗里多选分组并调整顺序（只能选自己有权用的分组）。
  - **自动**：顺序由系统按用户当前权限实时计算——有效订阅的分组排最前，其余按倍率从低到高，倍率相同按分组排序值。用户新开订阅、被授予或收回专属分组后自动生效，不用重建密钥。
- 工作台专用密钥改为**自动**模式；工作台模型目录 `/oauth/studio-models` 改为取该密钥当前全部分组模型的并集。
- 密钥列表与编辑弹窗显示「主路由 + 其余路由」及各组倍率，对齐截图里的交互。
- 上游已经开始处理、组内账号全部报错后**不**换组重试（本次不做，见 design.md 非目标）。

## Capabilities

### New Capabilities

- `api-key-multi-group-routing`：密钥与多个有序分组的绑定、手动/自动两种模式、网关选组规则、不带模型请求的处理、模型列表并集、缓存失效。
- `api-key-group-editor`：用户端「API 密钥」页多分组选择、排序、展示，以及对应的创建/更新接口字段。

### Modified Capabilities

无。仓库 `openspec/specs/` 下没有已发布的 capability。工作台桥接（`add-yingce-studio-bridge`，尚未归档）里「专用密钥绑定管理员指定的单个分组」的描述由本变更替换，在该变更的 design.md D4/D8 中同步更新。

## Impact

- **数据库**：新增 `api_key_groups(api_key_id, group_id, position)`；`api_keys` 新增 `group_mode`（`manual` / `auto`，默认 `manual`）。迁移把现有 `group_id` 回填为 position 0，不删除、不改名现有列。
- **后端**：
  - `service.APIKey` 增加 `GroupIDs` / `GroupMode`；认证缓存快照增加分组列表（缓存版本号递增，旧缓存自然失效）。
  - 新增选组服务，在 `APIKeyAuth`（含 Google 变体）里、设置分组上下文之前调用；下游 handler 看到的 `apiKey.Group` 就是选中的分组，不需要逐个改各平台 handler。
  - 计费、用量日志、订阅额度沿用现有「按 `apiKey.Group`」的逻辑，记录的是实际命中的分组。
  - Grok 视频创建时记录「请求 ID → 分组」，状态与内容查询按它取回分组。
  - `/v1/models` 等模型列表合并多个分组。
  - 分组、订阅、用户专属分组变更时，失效相关密钥的认证缓存（自动模式按用户失效）。
  - `oauthprovider`：工作台密钥创建为自动模式；模型目录取并集。
- **API**：`POST/PUT /api/v1/keys` 新增可选 `group_ids`、`group_mode`；不传时与现在完全一致。返回体新增 `group_ids`、`groups`、`group_mode`。
- **前端**：`KeysView.vue` 创建/编辑弹窗、列表分组列；i18n 中英文。
- **不影响**：管理员分组管理、渠道、账号、composite 分组内部路由、单分组密钥的全部现有行为。
